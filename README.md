# КВИЗ — живая викторина

Игра для компании примерно на 10 человек. Большой экран показывает код комнаты и QR-коды, игроки отвечают с телефонов, ведущий управляет вопросами со своего телефона. Вопросы и результаты лежат в Google Таблице, сервер — это Google Apps Script. Сайт можно опубликовать на GitHub Pages.

Секретов в репозитории нет. Токен ведущего и токен игрока создаются на сервере и в таблице хранятся только как SHA-256.

## Как это устроено

```text
index.html      экран телевизора: создание игры, QR, вопрос, рейтинг, итог
player.html     телефон игрока
host.html       панель ведущего
config.js       публичный адрес API
backend/*.gs    Google Apps Script
dev/server.mjs  локальная проверка без Google
```

Один запрос к API выглядит так:

```json
{ "success": true, "data": {}, "error": null }
```

При ошибке `success` равен `false`, а `error` содержит `code` и понятное сообщение. HTTP-статус у Apps Script обычно 200: смотрите поле `success`.

Игроки опрашивают сервер каждые 2 секунды, ведущий — каждые 1,5 секунды, телевизор — каждые 2 секунды. Страницы при этом не перезагружаются. Таймер считается от серверного времени `server_time` и момента открытия вопроса.

Баллы считает только сервер. Браузер не может прислать свой счёт, чужой ответ или правильный вариант до закрытия вопроса.

## Локальная проверка

Нужен Node.js 18 или новее. Google для этого шага не нужен.

```bash
npm start
```

Откройте http://127.0.0.1:8787/ . Пока `config.js` пустой, на localhost сайт сам обращается к `http://127.0.0.1:8787/exec`.

Автоматический сценарий на 10 игроков:

```bash
npm test
```

Он создаёт комнату, одновременно подключает 10 участников, проверяет лимит 20 игроков, одинаковые имена, одновременные ответы, обновление сессии, отказ менять ответ, отказ принять опоздавший ответ, однократное начисление баллов, ничью за первое место и итоговое распределение мест `1, 1, 3, 4, 4, 6, 7, 8, 8, 8`.

Локальный сервер повторяет правила настоящего API, но не заменяет Google Apps Script. Для настоящей игры нужен шаг ниже.

## 1. Таблица Google

1. Создайте пустую таблицу Google: https://sheets.new
2. Назовите её, например, «Викторина».
3. Откройте **Расширения → Apps Script**.

Скрипт окажется привязан к этой таблице. Отдельный файл базы создавать не нужно: `setupDatabase` сам добавит листы.

Таблица не должна быть открыта по ссылке для всего интернета. Скрипт читает её от вашего имени.

### Лист Questions

| Поле | Описание |
|---|---|
| id | Уникальный ID, например `q1` |
| order | Порядок |
| question | Текст вопроса |
| answer_a … answer_d | Варианты A–D |
| correct_answer | `A`, `B`, `C` или `D` |
| points | Баллы за верный ответ. Пустое значение считается как 100 |
| time_limit | Оставлено в таблице для совместимости. Ответ по нему не обрывается: вопрос закрывает ведущий |
| active | `TRUE` или пусто — вопрос участвует. `FALSE` — пропускается |

Первый запуск запишет 10 примеров, если лист пустой. Дальше редактируйте прямо здесь. Отдельной админки нет.

Вопрос попадает в игру только если заполнены текст, все четыре варианта и корректный ответ. Список вопросов фиксируется в момент старта: правки во время партии попадут уже в следующую игру.

### Лист Games

| Поле | Описание |
|---|---|
| game_id | ID сессии |
| room_code | Шестизначный код |
| host_token_hash | SHA-256 токена ведущего, не сам токен |
| status | `waiting`, `active`, `finished`, `archived` |
| current_question | ID текущего вопроса |
| question_phase | `none`, `open`, `closed`, `results` |
| question_opened_at, question_closed_at | Время открытия и закрытия, миллисекунды Unix |
| questions_json | Снимок вопросов этой партии |
| created_at, updated_at | Время создания и изменения |

`question_phase`, метки времени и `questions_json` нужны, чтобы отсчёт правильного ответа, рейтинг и несколько игр подряд не смешивались. Их не надо заполнять вручную.

### Лист Players

| Поле | Описание |
|---|---|
| player_id | ID игрока |
| game_id | ID игры |
| name | Имя |
| token_hash | SHA-256 токена игрока |
| total_score | Сумма баллов |
| joined_at | Время входа |

В одной комнате не больше 20 игроков. Имя уникально без учёта регистра. После старта новые игроки не принимаются.

### Лист Answers

| Поле | Описание |
|---|---|
| id | ID ответа |
| game_id, player_id, question_id | Связи |
| answer | `A`, `B`, `C` или `D` |
| is_correct | Заполняется при закрытии вопроса |
| points | Пусто, пока вопрос не закрыт. Потом число, в том числе 0 |
| answered_at | Время ответа |

Пустые `points` означают «ещё не начислено». Поэтому повторное закрытие вопроса не прибавляет баллы второй раз.

## 2. Apps Script

В редакторе Apps Script удалите содержимое `Code.gs` и создайте файлы с теми же именами, что в папке `backend`:

- `Code.gs`
- `Config.gs`
- `Database.gs`
- `Game.gs`
- `Players.gs`
- `Answers.gs`
- `Scoring.gs`
- `Utils.gs`

Скопируйте в каждый файл содержимое одноимённого файла из репозитория. Файл `appsscript.json` в редакторе открывается через **Настройки проекта → Показать файл манифеста**. Вставьте в него содержимое `backend/appsscript.json`, чтобы включился runtime V8. Если манифест уже содержит другие поля, сохраните их и проверьте, что `"runtimeVersion": "V8"`.

`SPREADSHEET_ID` в `Config.gs` оставьте пустым: привязанный скрипт и так видит свою таблицу.

### Первый запуск

1. В списке функций выберите `setupDatabase` и нажмите **Выполнить**.
2. Разрешите доступ к таблице от своего аккаунта.
3. В таблице появятся четыре листа и примеры вопросов. В журнале выполнения будет ссылка на таблицу.

Пока скрипт привязан к таблице, в ней есть меню **Викторина**:

- Создать листы и вопросы
- Архивировать старые игры
- Самопроверка

`runSelfCheck` создаёт тестовую комнату, отвечает на один вопрос, проверяет, что баллы не начисляются повторно, завершает игру и сразу архивирует комнату. Запускайте её после публикации, если нужно убедиться, что таблица и код на месте.

Игры старше 7 дней со статусом `finished` можно убрать из доступа функцией `archiveOldGames`. Строки не удаляются. Код архивной комнаты больше не открывается.

### Публикация Web App

1. **Развёртывание → Новое развёртывание**.
2. Тип: **Веб-приложение**.
3. Выполнять от имени: **меня**.
4. У кого есть доступ: **Все** или, если в списке два пункта, **Все, даже анонимные** (`Anyone, even anonymous`). Игроки не должны входить в Google.
5. Нажмите **Развернуть** и скопируйте URL. Он заканчивается на `/exec`.

Берите именно URL развёртывания `/exec`, а не `/dev` из редактора. Адрес `/dev` требует ваш вход и не подходит телефонам гостей.

После каждой правки кода откройте **Развёртывание → Управление развёртываниями → карандаш → Версия: новая версия → Развернуть**. Иначе сайт продолжит вызывать старый код. URL при этом обычно не меняется.

Проверка: откройте URL `/exec` в браузере. Ожидается JSON:

```json
{ "success": true, "data": { "ok": true, "version": "1.0.0" }, "error": null }
```

Если вместо JSON открывается страница входа Google, доступ к веб-приложению не анонимный.

## 3. GitHub Pages

1. Создайте репозиторий и отправьте туда только frontend: HTML, `config.js`, `assets`. Папку `backend` можно тоже хранить в репозитории — секретов в ней нет, — но на сайте она не используется.
2. В `config.js` вставьте URL развёртывания:

```javascript
API_URL: "https://script.google.com/macros/s/ВАШ_ID/exec",
```

3. **Settings → Pages → Branch: main, folder: / (root) → Save**.
4. Через минуту сайт откроется по адресу `https://ВАШ_АККАУНТ.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.

Сайт должен открываться по HTTPS. GitHub Pages это даёт сам. Не кладите в `config.js` токены, ключи и содержимое таблицы.

QR-коды строятся в браузере библиотекой [qrcodejs](https://github.com/davidshimjs/qrcodejs) (MIT), файл `assets/js/qrcode.min.js`. Внешний сервис для QR не нужен.

## Как провести игру

1. Откройте сайт на телевизоре и нажмите **Создать игру**.
2. На экране появятся код комнаты, QR игроков и QR ведущего.
3. Игроки сканируют первый код, вводят имя и ждут начала. Повторное открытие той же ссылки на том же телефоне восстанавливает игрока.
4. Ведущий сканирует второй код. В панели видны код, число игроков, список и кнопка **Начать игру**.
5. После старта у всех открывается первый вопрос. Справа на телевизоре виден рейтинг и зелёная точка у тех, кто уже ответил. Игрок выбирает один вариант. Кнопки блокируются, повторно ответ не принимается. Времени на ответ нет: ведущий закрывает вопрос сам.
6. Ведущий нажимает **Завершить вопрос**. Сервер закрывает приём, проверяет ответы и один раз начисляет баллы. Верный ответ даёт баллы этого вопроса, неверный ответ и пропуск — 0.
7. Телевизор на весь экран показывает правильный ответ и отсчёт от 5 до 1, затем сам открывает рейтинг: места смещаются, баллы доначисляются. После этого ведущий нажимает **Далее**.
8. **Далее** открывает новый вопрос. После последнего ведущий нажимает **Завершить игру**: на экране победитель, три призовых места и полная таблица. Места сортируются по сумме баллов. При равенстве место одно и то же, следующее пропускается: два лидера получают 1, следующий — 3.
9. **Создать новую игру** начинает отдельную комнату. Старые игроки и баллы в неё не попадают.

Критические кнопки ведущего спрашивают подтверждение. Правильный ответ не показывается игрокам и телевизору, пока вопрос не завершён.

## Диагностика

| Что видно | Что сделать |
|---|---|
| Страница входа Google вместо JSON | В развёртывании выберите анонимный доступ и URL `/exec` |
| «Не задан адрес API» | Заполните `API_URL` в `config.js` и заново опубликуйте Pages |
| «Сервер вернул непонятный ответ» | Откройте URL `/exec` отдельно. Если это HTML, развёртывание закрыто |
| Правка скрипта не работает | Создайте новую версию развёртывания |
| «Нет листа Questions» | В редакторе выполните `setupDatabase` |
| «Не удалось открыть таблицу» | Скрипт должен быть привязан к таблице либо `SPREADSHEET_ID` должен быть её ID |
| Вопрос не попал в игру | Проверьте `correct_answer` (только A–D), все четыре варианта и `active` |
| Правка вопроса не видна в текущей партии | Она применится к следующей игре. Счётчик вопросов в лобби обновляется примерно за 30 секунд |
| «Игра уже началась» | Комната уже запущена. Создайте новую или подключитесь тем же телефоном, если уже входили |
| «Это имя уже занято» | Выберите другое написание. Регистр не различается |
| «В комнате уже 20 игроков» | Это предел комнаты |
| «Ответ уже принят» | Вариант менять нельзя. Повтор той же отправки после обрыва сети безопасен |
| «На экране ещё идёт отсчёт» | После закрытия вопроса пять секунд показывается ответ. **Далее** станет доступна сразу после них |
| «Сервер занят» | Параллельная запись взяла блокировку. Запрос можно повторить: баллы второй раз не прибавятся |
| «Нет связи» на экране | Страница оставляет последние данные и пробует снова. Проверьте интернет и URL |
| Игрок обновил страницу | Телефон восстанавливает сессию по сохранённому токену. Игровое состояние остаётся в таблице |
| Старые комнаты мешают | Меню **Викторина → Архивировать старые игры** или кнопка **Архивировать** у ведущего после финала |
| Два устройства создали две игры | Так и задумано: у каждой свой код, свои игроки и свои ответы |

Журнал Apps Script: **Выполнения** в редакторе скрипта. Туда пишутся внутренние ошибки без токенов игроков.

Не сортируйте листы вручную во время живой игры. После партии это безопасно: перед записью скрипт сверяет ID строки.
